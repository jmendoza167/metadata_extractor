# Sample files

Small files to try metaex on, for example:

```
metaex risk tests/samples/jpeg/gps_camera.jpg
metaex show tests/samples/svg/editor.svg
metaex strip tests/samples/jpeg/kitchen_sink.jpg -o kitchen_sink_stripped.jpg
```

**All metadata in these files is fake.** The person is always "Jane Doe"
(`jane.doe@example.com`), GPS coordinates point at the Eiffel Tower
(48.8584 N, 2.2945 E), and camera names and serial numbers (`ExampleCam`,
`SN-0001`) are made up. The one local path, in `svg/editor.svg`, uses the
made-up user name `jane.doe`.

Every file outside `real/` is generated by `scripts/make_samples.py` from
the test helpers in `tests/helpers/` (not with Pillow or any other image
library), and is byte-for-byte the same on every machine. Don't edit them by
hand: change the generator, run `python scripts/make_samples.py`, and commit
the result. The tests run `python scripts/make_samples.py --check`, which
fails if a file is missing, differs or wasn't made by the generator.

The **risk** column is what `metaex risk` reports, as critical / high /
medium / low findings.

`expected/` holds snapshots of `metaex show --json` and `metaex risk --json`
for every valid sample, without the parts that depend on the machine: the
path, file times and permissions, the Mark of the Web, and the metaex
version. The tests compare the real output with them, and also check that
`strip` followed by `verify` is clean and that the pixels don't change. The
snapshots are never updated automatically. When a change in output is
intended, run `METAEX_UPDATE_SNAPSHOTS=1 pytest tests/test_samples_snapshots.py`
and review the diff before committing.

## Damaged files (`malformed/`)

metaex refuses to strip each of these, with an error that says what is
wrong, and writes nothing. `show` and `risk` report the damage as a warning
and show whatever they could read before it.

| File | Damage |
|---|---|
| `malformed/truncated.jpg` | `gps_camera.jpg` cut off in the middle of the image data, like an interrupted download |
| `malformed/bad_crc.png` | A `tEXt` chunk whose CRC doesn't match its contents |
| `malformed/broken_subblock.gif` | A comment whose sub-block claims 255 bytes, more than the rest of the file |
| `malformed/wrong_riff_size.webp` | A RIFF header that says the file is 100 bytes longer than it is |
| `malformed/entity.svg` | An XML `<!ENTITY>` declaration (refused: entities enable XML attacks) |

## Files from real software (`real/`)

`real/` is for files saved by real programs, because they hold metadata
that generated files don't. It is empty for now. Only add formats metaex
supports today: JPEG, PNG, GIF, WebP and SVG (for example from a phone
camera, GIMP or Inkscape). Document formats such as DOCX and ODT are
planned, not supported; the Office and LibreOffice items below are for when
they are. The generator never touches `real/`, but the other sample tests
include every file in it, so a file added there is tested like the others.

A real file carries the identity of whoever made it. **Only add a file you
made from scratch for this repository**, never one you already had. Before
you commit one:

- [ ] **Name:** set your name in the program to "Jane Doe" *before*
  creating the file:
  - Microsoft Office: File > Options > General > User name and Initials.
  - LibreOffice: Tools > Options > LibreOffice > User Data.
  - Inkscape: Document Properties > Metadata.
- [ ] **Remove personal information:**
  - Office: File > Info > Check for Issues > Inspect Document, then remove
    "Document Properties and Personal Information".
  - LibreOffice: File > Properties, untick "Apply user data", then
    "Reset Properties".
- [ ] **Organization:** use no company template, and leave the company,
  manager and author fields empty or set them to example values.
- [ ] **Comments and tracked changes:** they store your name, so either
  have none or make them as "Jane Doe".
- [ ] **Location:** turn location off in the camera app before taking a
  photo, and photograph something neutral (no faces, your home, windows,
  screens, documents or number plates).
- [ ] **Device:** a camera or phone writes its model, and often a serial
  number, into EXIF, and you can't turn that off. If you don't want your
  device made public, don't add a photo.
- [ ] **Paths:** save from a neutral folder such as `C:\samples\`, not from
  your user folder, because some programs store the save path in the file.
- [ ] **Times:** creation and edit times, and the time zone, end up in the
  file; that's acceptable, but be aware of it.
- [ ] **Check the result:** run `metaex show --structure` on the file and
  read every field. Then search the file's bytes for your name, user name,
  email address and computer name.
- [ ] **Run the tests:** they scan every sample for user paths and email
  addresses that aren't `@example.com`.
